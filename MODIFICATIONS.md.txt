## 🚀 Déploiement

### Option 1 : Déploiement sur **Netlify** (recommandé)

1. **Créez un compte** sur [Netlify](https://www.netlify.com/) (gratuit).
2. **Glissez-déposez** le dossier `baracca-website` dans l'interface Netlify.
3. **Attendez** quelques secondes : votre site sera en ligne !
4. **Personnalisez** le nom de domaine (ex: `baracca.netlify.app`).

> ✅ **Avantages** : Déploiement en 1 clic, SSL automatique, formulaires gérés (Netlify Forms).

---

### Option 2 : Déploiement sur **GitHub Pages**

1. **Créez un dépôt GitHub** (ex: `baracca-website`).
2. **Poussez** le code dans le dépôt.
3. **Activez GitHub Pages** :
   - Allez dans **Settings > Pages**.
   - Sélectionnez la branche `main` et le dossier `/ (root)`.
   - Cliquez sur **Save**.
4. **Votre site sera disponible** à l'URL : `https://votre-utilisateur.github.io/baracca-website/`

> ⚠️ **Note** : Les formulaires ne fonctionneront pas avec GitHub Pages (utilisez Netlify).

## ⚙️ Personnalisation

### 1. Modifier le contenu
- **Textes** : Éditez directement les fichiers `.html` avec un éditeur de code (VS Code, Sublime Text, etc.).
- **Images** : Remplacez les images dans `assets/images/` par vos propres visuels.
- **Couleurs** : Modifiez les variables CSS dans `assets/css/style.css` (ex: `--primary: #4A9B8E;`).

Dans le fichier `investir.html` et `investisseurs.html`, modifiez la valeur :

Actualités de l'espace investisseurs alimentées par le blog

La section « Actualités » de `investisseurs.php` affiche désormais les
derniers articles publiés sur le blog (`blog.baracca.fr`), au lieu de
cartes écrites à la main.

Fonctionnement :
- Le blog expose un flux JSON public : `blog.baracca.fr/api-articles.php`
  (articles publiés uniquement : slug, titre, catégorie, date, extrait).
- `includes/blog.php` récupère ce flux (timeout 5 s) et construit les
  liens vers le blog : relatifs en local (`../blog.baracca.fr`), absolus
  en ligne (`https://blog.baracca.fr`).
- Si le blog est injoignable, la section affiche un message discret
  sans casser la page.

Formulaire de contact fonctionnel (send_contact.php)

Le formulaire de contact.php était prévu pour Netlify Forms (attribut
`netlify`, pas d'action) : hors Netlify, l'envoi ne fonctionnait pas.
Il poste désormais vers `send_contact.php` (méthode POST) :

- validation des champs (nom, email valide, message) ;
- envoi à invest@baracca.fr par mail() (Reply-To = l'email du visiteur) ;
- limitation de débit : 3 messages par heure et par adresse IP
  (data/contact-rate-limit.json) ;
- retour sur contact.php avec un message (?contact=success / error / rate).

Note : l'envoi dépend de la fonction mail() du serveur (sendmail/SMTP
configuré côté hébergeur).

Back-office : chiffres clés, documents et accès investisseurs

Un back-office est disponible à l'adresse /admin/ (identifiant `admin`,
mot de passe défini dans config.php — à changer après la première
connexion). Session sécurisée, limitation de débit (5 échecs / 15 min
par IP) et jetons CSRF sur tous les formulaires.

- Chiffres clés (admin/stats.php) : modifie les valeurs affichées sur
  l'accueil, la page « Investir » et l'espace investisseurs (euros
  collectés, objectif, investisseurs, modules déployés, modules en
  production, demandes en attente). Stockées dans data/stats.json.
- Documents (admin/documents.php) : upload (PDF, Excel, Word, CSV,
  images, ZIP — 10 Mo max) et suppression des documents de l'espace
  investisseurs (assets/documents/). telecharger.php délivre
  désormais tout fichier de ce dossier ayant une extension autorisée
  (la liste blanche en dur a été supprimée).
- Accès investisseurs (admin/investisseurs.php) : création de comptes
  individuels (email + mot de passe, 8 caractères min.), réinitialisation
  du mot de passe et suppression. Stockés dans data/users.json (hash
  bcrypt, jamais de mot de passe en clair).
- L'espace investisseurs se connecte désormais avec un email et un mot
  de passe personnels. L'ancien mot de passe unique partagé ne
  fonctionne plus : chaque investisseur doit recevoir ses identifiants
  depuis le back-office.
